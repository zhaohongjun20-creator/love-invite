# 约会小软件 · 二次元版（微信小程序）

在原 `love_invite.html`（约会邀请单页）的基础上重做成的**微信小程序工程**，
加入了会变表情的**韩漫/条漫风格二次元少女立绘**，流程从「一次性勾选」升级成
「封面 → 三步约会设置 → 带立绘的清单卡片」的完整小软件。

六位角色（3 女 3 男）各有 5 张 AI 生成的立绘，随流程自动切换表情；每套立绘配套一整套界面主题色，切换角色即整页换肤。画风：韩漫条漫写实风。

原单页 HTML 版保留在 `web/love_invite.html`，仍可直接双击打开。

## 一、怎么跑起来

1. 打开 **微信开发者工具** → 导入项目 → 目录选 `love-date-miniprogram`
2. AppID 选「**测试号**」（工程里已填 `touristappid`，可直接跑）
3. **「构建 npm」**：云服务 SDK 是 npm 包，运行前需要它的构建产物。
   仓库里**已经带好了** `miniprogram_npm/@tencent-ai/workbuddy-cloud-sdk/miniprogram.js`，
   所以这一步可以跳过；如果你改动了 `package.json`，再点一次「工具 → 构建 npm」重新生成即可。
4. 编译即可看到封面页

> 想立刻看效果但不想开开发者工具？直接双击 **`preview.html`**。
> 它是**单文件自包含**的（立绘已内联成 base64，419KB），双击即开、也能直接发给别人看；
> 含角色切换、完整流程、BGM、卡片生成。
> 换了 `assets/char/` 里的立绘之后，跑一次 `python tools/inline_preview_images.py` 重新内联即可。
> （预览版是纯前端的展示页，不连云端；邀请码 / 回复这类双人功能要在小程序里用。）

## 三、二次元形象怎么做的

**默认方案：AI 生成的韩漫/条漫风格立绘（CogView）**，**3 女 3 男六套**，封面上一键切换，且每套角色自带专属界面主题色。

| 套装 | 角色 | 立绘位置 | 包体 |
|---|---|---|---|
| 类别 | 角色 | 立绘路径 | 主题 |
|---|---|---|---|
| 女生 | 小桃 | `assets/char/*.jpg` | 樱花粉 |
| 女生 | 星柠 | `assets/char/girl2/*.jpg` | 星夜蓝紫 |
| 女生 | 柚茶 | `assets/char/girl3/*.jpg` | 暖橘 |
| 男生 | 小川 | `assets/char/male/*.jpg` | 青蓝 |
| 男生 | 墨白 | `assets/char/male2/*.jpg` | 墨绿文艺 |
| 男生 | 炎阳 | `assets/char/male3/*.jpg` | 红黑热血 |

半写实五官、细线稿、发丝分缕、柔和渐变上色 —— 也就是那种「条漫男主女主」的质感。

一致性是重点：每套都先出 1 张基准图（`normal`），其余 4 张全部**以基准图做图生图**，
只改表情，所以同一套里的 5 张是同一个角色、同一套衣服、同一个背景和光照。

| 心情 | 触发场景 | 画面 |
|---|---|---|
| `normal` | 步骤 2 地点 | 温和微笑，正视前方 |
| `shy` | 步骤 1 时间、点「再想想」 | 脸红、眼神躲开（女生双手绞衣角／男生摸后颈） |
| `happy` | 封面 | 弯月眼 ∩、开怀大笑、头微侧 |
| `excited` | 步骤 3 干什么 | 眼睛放光、张嘴惊呼 |
| `love` | 生成清单 | 含情半眯眼、脸红、周围飘心 |

**切换**：封面角色下方有「👧 女生 / 👦 男生」胶囊，选完记在本地，下次打开还是这套。
想改默认、加第三套或换立绘，只动 `config/character.js`。

**呈现方式**：组件用圆角相框（白描边 + 柔和投影）承载立绘，尺寸严格按 720×1021 的比例，
`aspectFill` 不会裁到脸：

| size | 相框尺寸 | 用在哪 |
|---|---|---|
| `lg` | 440×624rpx | 封面 |
| `md` | 360×511rpx | 邀请流程 |
| `sm` | 260×369rpx | 邀请码 / 答复 / 清单页 |

调用方式（任意页面）：

```html
<anime-girl mood="shy" size="md" set="{{charSet}}" talking="{{true}}" />
```

`set` 传 `girl` / `boy`（留空则用用户选中的那套）。

**兜底方案**：组件里还留着一套纯 WXSS 手绘的矢量少女（`.stage` 部分）。把某一套的
`useImage` 改成 `false` 就切回矢量，不依赖任何图片，体积为零。

## 四、想换形象？改一个文件就行

**换成你自己的立绘**（同一尺寸 720×1021，或任意比例都行，相框会自动裁）：

1. 把 5 张图放进 `assets/char/`，命名为 `normal / shy / happy / excited / love`
2. 打开 `config/character.js`，把 `images` 里的路径指向新文件

**退回矢量形象**：`useImage: false`。

两种方式都**不用改任何页面代码**——组件自己换渲染方式，表情切换逻辑照常工作。

> 换角色形象时，生成的一致性和本次一样：先定 1 张基准图，其余用图生图只改表情。

## 五、★ 云端后端（两个人真正能互动的部分）

> **⚠️ 1.1.0 迁移说明：后端已从 WorkBuddy HTTP 接口迁移到微信云开发。**
> 原因：旧接口域名 `mp-api.app.workbuddy.host` 查不到 ICP 备案记录，无法配置进
> 「request 合法域名」白名单，正式版里所有云端请求都会静默失败 —— 这就是之前上线失败的最可能原因。
> 迁移后接口走 `wx.cloud.callFunction`，**不需要配置任何服务器域名，也不依赖域名备案**。
>
> **部署三步**（需要自己的 AppID，测试号不支持云开发）：
> 1. 微信开发者工具导入本项目 → 工具栏「云开发」→ 开通（选按量付费即可，有免费额度）
> 2. 在 `cloudfunctions/` 下对 `date_invite_create / date_invite_get / date_invite_answer`
>    三个函数分别右键 →「上传并部署：云端安装依赖」（数据集合 `date_invites` 首次调用自动创建）
> 3. 真机预览走一遍：发起 → 分享 → 答复 → 回看；`config/cloud.js` 的 `cloudEnv` 可留空（默认环境）
>
> **离线兜底**：云端未开通/未部署时，应用自动降级为「本机演示模式」（同一台手机上全流程可走，
> 邀请码不出本机），页面不会报错白屏 —— 这也是给审核兜底：就算云没配好，审核员打开也能走完流程。
>
> **内容安全**：邀请与答复里的自由文本（称呼/时间/地点/活动/留言）都会在云函数里过
> `security.msgSecCheck`，命中即拒 —— 这是个人主体小程序带 UGC 过审的硬要求。
>
> **提审清单（个人主体）**：
> - 类目建议选「工具 > 效率」或「生活服务」，不要选社交/婚恋类目（个人主体无资质会被驳回）
> - 微信后台「用户隐私保护指引」声明：剪贴板（复制邀请码）、相册（仅写入，保存卡片）
> - 提审时在「审核备注」说明：邀请码即凭证、无需注册登录，无外部链接、无支付
> - 每周可提交 3 次正式版审核；被驳回时分享面板会展示微信返回的完整审核原因
>
> （以下为 1.0.0 时的旧版说明，数据结构与安全模型不变，仅存储从 WorkBuddy 换成云开发数据库）

原来这套东西只能在一台手机上自己玩：选完时间地点，生成一张卡片。加了云端后端之后，
**发起和答复可以发生在两台手机上**。

### 用起来是什么样

| 谁 | 做什么 |
|---|---|
| 你 | 封面点「发起约会邀请」→ 三步选好 → 云端生成一个 **6 位邀请码** |
| 你 | 把邀请码发给 TA（或者直接用「直接发给 TA」分享小程序卡片，码会带在链接里） |
| TA | 打开小程序 → 自动/手动输入邀请码 → 看到你的约会方案 → 选「我答应！」/「想改个时间」/「换个地方」+ 留句话 → 提交 |
| 你 | 回「我发起的邀请」看 TA 的回复；封面上还会显示「有 N 条回复」 |

**接收方不需要注册登录**——约会邀请要人先注册，就没人会填了。所以用「邀请码」当凭证：
码本身是随机的 6 位、只有拿到码的人才能读到这条邀请。

### 数据怎么存的

云端一张表 `date_invites`，存发起人、约会方案、答复、留言、时间戳。

安全上做了一个取舍：**表本身不开放给前端**（开启了 RLS 且不建任何策略），前端只能通过三个
服务端函数按码访问：

| 函数 | 作用 |
|---|---|
| `date_invite_create(...)` | 生成不重复的邀请码并写入，返回码 |
| `date_invite_get(codes[])` | 按码批量读取（你查 1 条，我查自己的一串） |
| `date_invite_answer(code, ...)` | 写入答复，返回更新后的行 |

这样即使前端凭证泄露，也没法枚举别人的邀请——**必须知道码**。

### 换一个云环境

`config/cloud.js` 里的 `cloudEnv` 填成新的环境 ID 即可，其余代码不用动（留空 = 默认环境）。

### 上线前提交审核清单（个人主体）

| 项 | 怎么做 |
|---|---|
| AppID | `project.config.json` 换成自己的正式 AppID（`touristappid` 不能上线，也不支持云开发） |
| 小程序备案 | 微信公众平台 → 设置 → 基础设置里完成小程序备案（正式版发布的硬前提，与代码无关） |
| 类目 | 建议「工具 > 效率」或「生活服务」；不要选「社交」，个人主体没有该资质 |
| 隐私保护指引 | 公众平台 → 设置 → 服务内容声明里勾选：剪贴板、相册（保存卡片）、用户填写内容 |
| 真机自测 | 体验版走通：发起 → 分享卡片 → 对方输码答复 → 我发起的邀请里看到回复 |
| 提审说明 | 版本描述里写清：邀请码即凭证、无需注册登录；演示路径（发起→分享→答复） |
| 提审频率 | 每周 3 次正式版审核机会，先发体验版验证再提审，别浪费次数 |

> 注意：`preview.html` 是纯前端展示页，不连云端；邀请码 / 答复要在小程序里跑。

## 六、背景音乐（F 大调 · 浪漫·激情版）

不用音频文件，全部是 WebAudio 现场合成（零版权、零体积）。见 `utils/music.js`：

| | 最初 | 现在 |
|---|---|---|
| 调性 | A 小调（Am–F–C–G） | **F 大调**，Dm–Bb–F–C 情感向进行，和弦带七度/九度 |
| 速度 | 2 秒一小节 ≈ 60 BPM | **112 BPM**（一小节 2.14 秒），速度翻倍 |
| 声部 | 八音盒琶音 + 单音旋律 | **四层**：低音推进 / 长音和弦垫 / 八分音符琶音 / 主旋律 |
| 动态 | 无 | 8 小节一个**渐强**，第 4、5 小节到高潮（最高音 F5） |
| 音色 | 正弦 + 三次泛音 | 低音正弦、和弦垫三角波慢起慢收、高音铃铛点缀 |

节奏上还用了后半拍的推音（每小节第 4 拍后半拍补一下低音）来制造推动感，
主旋律走 A4→F5 的起伏，第 4 小节落在 F5 上，是整段的情绪点。

**想先听一下**：`docs/bgm-preview.wav` —— 用同一套编曲离线渲染的 19 秒试听。

**改曲子**：`utils/music.js` 里的 `BARS` 数组，一小节一行
（`bass` 低音 / `pad` 和弦垫 / `arp` 琶音 / `mel` 主旋律），换和弦与旋律即可，其它代码不用动。
网页预览版 `preview.html` 里有一份等价的实现，改完记得同步。
